# Key engineering decisions

| # | Decision | Why | Trade-off |
|---|----------|-----|-----------|
| 1 | **pgvector + Postgres full-text in one database** instead of a separate vector DB | One transactional store for tenancy, chunks, vectors and FTS; `workspace_id` filters are plain SQL; fewer moving parts | Very large corpora (>10M chunks) would want a dedicated ANN service |
| 2 | **Hybrid retrieval fused with Reciprocal Rank Fusion** (k=60) | Vector search misses exact terms (IDs, numbers, acronyms); FTS misses paraphrases. RRF needs no score calibration between the two | Two queries per search (~ms each with HNSW + GIN) |
| 3 | **OR-of-keywords `to_tsquery`** rather than `websearch_to_tsquery` | Natural-language questions are long; AND semantics returned nothing for most questions. Keywords are `[a-z0-9]+` so the string is injection-safe (still a bound parameter) | Lower FTS precision, recovered by the reranker |
| 4 | **Reranker scores normalised to [0, 1]** | Lets the "insufficient context" guardrail use one threshold (`MIN_RELEVANCE`) whatever the reranker (lexical, Cohere, none) | Threshold must be recalibrated when switching reranker/embeddings |
| 5 | **Guardrail before generation** | If the best chunk is below the threshold we return a fixed refusal and skip the LLM: zero hallucination risk and zero cost for out-of-scope questions | Some answerable-but-poorly-phrased questions are refused; logged as `grounded=false` for review |
| 6 | **Contextual chunk headers** (section heading prepended to each chunk) | Found by a failing test: "and what about security?" could not match the *Security* section because the body never says "security". The header fixes both embedding and FTS recall | Slightly longer chunks |
| 7 | **Query rewriting only when history exists**; the standalone question is used for retrieval *and* answering | Follow-ups ("and what about X?") are unretrievable on their own | One extra (small) LLM call per follow-up |
| 8 | **Pluggable providers behind a 2-method Protocol** (`stream`, `complete`) + a deterministic **fake extractive LLM** and **hashing embedder** | Whole system, CI and demo run with zero API keys; tests are deterministic. Real providers are one env var away | Fake answers are extractive, not fluent |
| 9 | **SSE over `fetch` (not EventSource)** | EventSource can't POST or send Authorization headers; SSE is simpler than WebSockets for one-way token streams and works through proxies (`X-Accel-Buffering: no`) | Manual SSE parsing on the client (unit-tested) |
| 10 | **Opaque, hashed, rotating refresh tokens with family reuse detection**; short-lived JWT access tokens | Stolen refresh token reuse revokes the whole family (OWASP recommendation); DB only stores SHA-256 hashes | A DB lookup per refresh |
| 11 | **404 (not 403) for workspaces you are not a member of** | Prevents probing workspace IDs across tenants | Slightly less explicit errors |
| 12 | **Celery for ingestion/eval, with an `inline` mode** | Parsing/embedding is slow and must not block requests; `inline` keeps tests hermetic without Redis | Two code paths for dispatch (tiny, in `services/jobs.py`) |
| 13 | **RAGAS-style metrics implemented in-house** (faithfulness, answer relevancy, context precision/recall) with heuristic or LLM judge | The `ragas` package pulls a large LangChain stack and always needs an LLM judge; in-house metrics follow the same definitions, run offline in CI, and use the configured LLM as judge when available | Heuristic judge is lexical, so absolute numbers are indicative; compare runs relatively |
| 14 | **Embedding dimension fixed at migration time** (`EMBEDDING_DIM`, default 768; OpenAI/Gemini asked for 768 dims, Ollama vectors truncated+renormalised) | HNSW indexes need a fixed dimension | Changing embedding model requires re-migration and re-indexing |
| 15 | **URL ingestion SSRF guard** (scheme allow-list, DNS resolution, private/link-local/metadata IPs blocked, re-checked after redirects) | URL ingestion is a classic SSRF vector into cloud metadata endpoints | Can't ingest intranet URLs (by design) |
| 16 | **Rate limiting: fixed window in Redis, in-memory fallback**; stricter limit on auth endpoints | Consistent limits across replicas; brute-force protection on login | Fixed windows allow short bursts at window edges |
| 17 | **MinIO image `coollabsio/minio`** (overridable via `MINIO_IMAGE`) | The official `minio/minio` image is no longer pullable from Docker Hub on this setup; any S3-compatible store works since storage goes through boto3 | Community-maintained image |
